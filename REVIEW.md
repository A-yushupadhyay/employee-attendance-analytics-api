# REVIEW.md

Defects found in the starter `app/main.py` (line numbers refer to the **original** starter). Every item was confirmed by reading the code; the fixed behaviour is covered by `tests/test_rules.py` (no database) or `tests/test_api.py` (needs MongoDB).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes`, l.33-37 | Takes the shift start from `punch_in.replace(...)`, i.e. the UTC/server-local date and hour, not IST. Overnight shifts are ignored. | A 10:05 IST punch (04:35 UTC) is compared with 09:30 on the UTC clock, looks 'early', and reports 0 late minutes (contract: 35); a 00:30 IST punch for a 22:00 shift is not counted late. | `shift_bounds()` builds the shift start/end in IST from the attendance date and rolls an overnight end to the next day; `compute_late_minutes` uses it. |
| 2 | `compute_late_minutes`, l.36-37 | Floors to whole minutes **before** the `> 10` test, so the grace check is not on seconds. | Punch-in 09:40:01 gives `int(10.02)=10`, `10 > 10` is False, so late = 0 (contract: 10). 09:40:00 and 09:40:01 should differ. | Compare the exact seconds against 600 (strict `>`), then floor to minutes since shift start. Unit tests cover 09:40:00 / 09:40:01 / 10:15:59. |
| 3 | `compute_work_hours`, l.40-41 | `round()` on a float is banker's / binary rounding, not half-up (R4). | 18 s = 0.005 h returns 0.0 (expected 0.01); 16182 s = 4.495 h returns 4.49 (expected 4.50). | `round_half_up()` does exact integer arithmetic: `floor(secs*100/3600 + 1/2)/100`. |
| 4 | `compute_overtime`, l.44-47 | Returns any positive minute count; there is no 30-minute minimum (R3). Overnight shift end is not moved to the next day, and the result is never used (the starter never sets overtime on punch-out). | Leaving 10 minutes after shift end reports 10 overtime minutes (expected 0). An overnight (22:00-06:00) worker leaving at 06:40 next day gets about 1480 minutes of overtime, because the shift end is placed on the *same* date as the shift start. | `compute_overtime` returns the floored minutes only if `>= 30`, measured against the overnight-aware shift end. |
| 5 | `punch_in`, l.101 and l.113 | An unknown `emp_code` makes `emp` `None`; `emp["shift_start"]` raises `TypeError`, which is an HTTP 500. | `POST /attendance/punch-in {"emp_code":"NOPE"}`. | `get_employee_or_404()` returns 404 first. |
| 6 | `punch_in`, l.102 | `if body.punched_at` treats 0 as "missing"; `fromtimestamp()` without tz gives a **naive server-local** datetime; milliseconds are kept (contract: truncate to whole seconds); nothing rejects seconds, floats, strings or booleans. | Run the server in a non-UTC zone: stored instants shift. `punched_at: 1783312500` (seconds) is accepted as a 1970 date. | `EpochMs` strict integer type with a sane range (422 otherwise); `ms_to_dt()` builds an aware UTC datetime truncated to seconds; `None` check, not truthiness. |
| 7 | `punch_in`, l.103 | The attendance date is the date of the naive local timestamp, not the IST date, and ignores overnight shifts (R1). | A punch at 00:10 IST while the server runs in UTC lands on the previous date; an overnight worker's 01:00 punch is dated "today" instead of the day the shift started. | `attendance_date()` converts to IST and, for overnight shifts, subtracts a day when the punch is before `shift_end`. |
| 8 | `punch_in`, l.104-118 | Check-then-insert race: two simultaneous requests both pass `find_one` and both insert (no unique index exists). | Fire 10 parallel punch-ins: several return 201 and duplicate records appear. | Unique index `(emp_code, date)` created at startup; `insert_one` only; `DuplicateKeyError` becomes 409. Tested with 12 threads. |
| 9 | `PunchInIn.status`, l.34 / `punch_in` l.109 | `status` is a free string: `ABSENT`, `LEAVE` or `"banana"` are accepted on a punch-in. | `{"status":"ABSENT"}` returns 201 with a punch time. | `PresenceStatus = Literal["PRESENT","WFH","ON_DUTY"]`, so anything else is 422. |
| 10 | `punch_in` response, l.113-121 | Never computes `half_day`/`overtime`/`work_hours` via one function; leaks an `id` field; returns raw `datetime` objects (not epoch ms); response not the `AttendanceRecord` schema. | Response has `"id"` and ISO datetimes instead of integers. | `serialize_attendance()` returns exactly the schema (ms integers, no `_id`/`id`, defaults for legacy documents). |
| 11 | `create_employee`, l.79-83 | Check-then-insert race, no unique index; no validation (bad `emp_code`, email, `HH:MM`, `shift_start == shift_end`, impossible dates); `created_at = datetime.now()` is naive local time and returned as a datetime, not epoch ms. | Two parallel creates both succeed; `{"shift_start":"9:3"}` is accepted. | Pydantic patterns + validators (422); unique `emp_code` index and `DuplicateKeyError` -> 409; `created_at` stored as a BSON date, returned as ms. |
| 12 | `list_employees`, l.93-96 | `skip = page * page_size` skips a whole page (page 1 returns the second page); `total` ignores the department filter; no sort so pages are not stable; no bounds on `page`/`page_size`. | Seed 3 employees, `?page=1&page_size=2` returns 1 item; `?department=X` shows `total` of everyone. | `skip=(page-1)*page_size`, `count_documents(filter)`, sort by `emp_code`, `page>=1`, `1<=page_size<=100` (422). |
| 13 | `list_attendance`, l.133-152 | `find(q)` loads **every** matching document into Python, then sorts and slices in Python; sorts by `date` only (ties are unordered); `total` is `len()` of that list; no index, so a full collection scan. | With 100k records every page request reads all of them (seconds, memory). | Server-side `find().sort(date desc, emp_code asc).skip().limit()` + `count_documents`, supported by the `date_emp` / `status_date_emp` / `uniq_emp_date` indexes. |
| 14 | `list_attendance`, l.133-152 | No validation: `date_from > date_to`, malformed dates, unknown `status`, `page_size=100000` are all accepted; response leaks `id` and raw datetimes/history values. | `?date_from=garbage`, `?status=NOPE`, `?page_size=100000` return 200. | Date regex + real-date check, range check, `Status` literal, `Query` bounds (all 422); shared serializer. |
| 15 | `MongoClient`, l.22 | No `tz_aware=True`, so PyMongo hands back **naive** datetimes; mixing them with the aware IST datetimes in `compute_overtime` raises `TypeError`; no server selection timeout. | `punch_out - end` fails with "can't subtract offset-naive and offset-aware datetimes". | `MongoClient(..., tz_aware=True, serverSelectionTimeoutMS=5000)`; `as_utc()` guards the conversion. |
| 16 | `health`, l.72-74 | Always returns ok, even if MongoDB is down. | Stop MongoDB: `/health` still says ok, every other endpoint fails. | Pings MongoDB; 503 if unreachable. |
| 17 | whole file | No indexes are created anywhere, and the one-record-per-day invariant is not enforced by the database. | `explain()` of any query shows COLLSCAN; duplicates possible. | `ensure_indexes()` at startup (idempotent), see DECISIONS.md. |

## Looked at and decided NOT a defect

* `load_dotenv()` (l.20): its default is `override=False`, so real environment variables already win over `.env`, which is what the contract asks for. Left as is.
* `list_attendance` paging arithmetic `(page - 1) * page_size` (l.149): correct (unlike `list_employees`). I only moved it into the database.
* Comparing `date` strings with `$gte`/`$lte`: correct for zero-padded `YYYY-MM-DD`; kept.
* Popping `_id` before returning (l.84, l.120): fine in itself, but the extra `id` field it adds is the defect noted in #10.
* `datetime.fromisoformat(date_str)` in `compute_overtime`: valid for `YYYY-MM-DD`; only the missing overnight/threshold handling is wrong (#4).
